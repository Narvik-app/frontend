# Documentation / about screenshots

The images of the documentation (`documentation` repo) and of the about website (`narvik-about` repo) are generated by
Playwright from the backend dev fixtures, then converted to `.webp` (quality 100, 2000 px wide at most).
Nothing is taken by hand anymore, except the images listed in [What can't be generated](#what-cant-be-generated).

```
narvik-back fixtures ──► Narvik (dev server) ──► Playwright ──► png ──► sharp ──► webp
 (make reload-fixture)                          (manifest.ts)               out/docs/…   out/about/…
```

## Run it locally

1. Start the backend and reload the fixtures **right before** the capture (some dates are relative to the load time):
   ```bash
   cd ../narvik-back && make start && make reload-fixture
   ```
2. In this repo (the API url, certificates and Nuxt env are the same as for the e2e tests, see `playwright.config.ts`):
   ```bash
   pnpm install
   pnpm exec playwright install chromium   # once
   pnpm screenshots                        # everything
   SCREENSHOT_ONLY=tt-,loan- pnpm screenshots   # only the ids starting with these prefixes
   ```
3. The result is in `tests/screenshots/out/` (git ignored):
   - `out/docs/…` → copy at the root of `docs/` in the **documentation** repo
   - `out/about/…` → copy in `public/pics/` in the **narvik-about** repo

Generated images are always written in a **`generated/` subfolder** next to the manual ones, so it is obvious which image is synced
and which one is manual (see [Where the images go](#where-the-images-go)).

In CI the same thing is done by the [Generate screenshots workflow](#ci), which also opens the pull requests.

## Files

| File | Role |
|---|---|
| `manifest.ts` | Single source of truth: every generated image is declared here |
| `screenshots.spec.ts` | Playwright test: one test per manifest entry, writes the png in `out/png` |
| `convert.ts` | Converts the png to webp (`sharp`) and dispatches them per repository, run after the tests by `pnpm screenshots` |

The Playwright project is `screenshots` in `playwright.config.ts`: Chromium only, viewport 1680x1000 at 2x (sharp text, `convert.ts` then downsizes to 2000 px wide at most), `fr-FR` locale,
`Europe/Paris` timezone, reduced motion. It depends on the `setup` project (login states of `tests/e2e`).

## Where the images go

A target `path` in the manifest is written with a `generated` folder inserted by `convert.ts`:

| Target | Manifest `path` | Written to |
|---|---|---|
| `docs` | `` `${DOCS_LOAN}/loans-list` `` | `docs/frontend/docs/pret/images/generated/loans-list.webp` |
| `about` | `loan` | `public/pics/generated/loan.webp` |

Everything in a `generated/` folder is overwritten by the next run (don't edit it by hand), everything next to it is manual.
The doc pages reference `./images/generated/<name>.webp` and the about components `/pics/generated/<name>.webp`.

## Add or change an image

Add an entry in `manifest.ts`:

```ts
{
  id: 'loan-liste-prets',            // unique, prefix by module, used by SCREENSHOT_ONLY
  role: 'ADMIN',                     // login state (see STORAGE_STATE in tests/e2e/utils/auth.ts)
  url: '/admin/loans',
  prepare: async (page) => { … },    // optional: open a modal, fill a form, navigate…
  locator: dialog,                   // optional: crop on an element (modal, card…)
  targets: [
    {repo: 'docs', path: `${DOCS_LOAN}/loans-list`},   // docs/frontend/docs/pret/images/generated/loans-list.webp
    {repo: 'about', path: 'loan'},                      // narvik-about/public/pics/generated/loan.webp
  ],
}
```

One capture can feed several images (docs and/or about). Other options:

| Option | Effect |
|---|---|
| `fullPage` | Capture the whole scrollable page instead of the viewport |
| `crop` | `'content'`: only the main content (no header, menu nor footer). `'page'`: the whole viewport. Default: `'content'` for images only used in the documentation, `'page'` when an `about` target exists (marketing images keep the menu) |
| `clipHeight` | With `crop: 'content'`, keep only the top N css pixels of long pages |
| `locator` | Crop on this element (takes precedence over `crop`) |

Helpers at the top of `manifest.ts` (`dialog`, `cardWith`, `addToCart`, `selectSeller`…) cover the common steps.
Prefer `data-testid` / roles over css classes, and add a `data-testid` in the app when a selector is fragile.

Conventions:

- File names are **English, kebab-case** (`loans-list`, `sale-list-2`, `my-declarations`), always `.webp`.
  The doc folders (`pret`, `temps-kilometres`…) keep their French names since they are part of the page URLs.
- After adding an image, reference it in the doc page (`![…](./images/generated/name.webp)`) and in `FeatureList.vue` for the about site.
- Check the permissions of the role: for instance supervisors don't have the loan permissions by default, use `ADMIN`.

## Fixtures

Everything shown comes from `narvik-back/src/DataFixtures/AppFixtures.php` (+ the Foundry factories and stories in `narvik-back/tests`):

- generic, association-friendly vocabulary (activities, inventory, loan items), French faker locale, **seeded faker** so the data is the same on every load
- demo images (club logo, avatars, loan items) in `narvik-back/tests/fixtures/demo/`, imported through `ImageService`
- featured account `admin@club1.fr` (club admin) with a presence history, today's presence, an overdue yearly control, an expired medical certificate, time & travel declarations…
- locked and draft time & travel exports with attestations

When a screenshot needs data that doesn't exist (a state, a badge, a list…), add it to the fixtures rather than creating it in `prepare`.
Dates are relative to the load time (`-14 months`, `today`…): this is why the fixtures must be reloaded before the capture.
The logins and fixed UUIDs are also used by the e2e tests: don't change them.

## Stability tips

`screenshots.spec.ts` already waits for the network, fonts, skeletons and spinners (twice, as download links only start loading after the render),
hides the Nuxt devtools badge and the sticky header (content crops), and disables animations.
Charts (Chart.js) animate on render and on every resize: the test waits until all the canvases are drawn and unchanged for 2 seconds, and a `fullPage` capture resizes the
viewport to the page height *before* waiting, then takes a plain viewport screenshot (letting Playwright resize it during the capture redraws the charts mid-animation).
If an image is still captured half-loaded, wait for a specific element in `prepare`.
Random data must stay out of the images: seed it in the fixtures instead.

## CI

`.github/workflows/screenshots.yml` (**Generate screenshots**):

- Trigger: manual (`workflow_dispatch`, inputs: backend ref, base branch of the docs PR, base branch of the about PR, `threshold`, `force`) or when a release is published.
  The workflow has to exist on the default branch to be dispatched.
- `generate` job: same stack as the e2e workflow (backend built from `Narvik-app/backend`, fixtures reloaded, Nuxt dev server), runs `pnpm screenshots`, [drops the unchanged images](#unchanged-images) and uploads `tests/screenshots/out` as the `screenshots` artifact.
- `publish` job (matrix `documentation` / `about`): generates a token with the GitHub App (`FROOZEIFY_APP_CLIENT_ID` / `FROOZEIFY_APP_PRIVATE_KEY`, installed on the whole organisation),
  copies the images (`docs/` or `public/pics/`) and opens the `chore: Update screenshots` pull request on branch `ci/screenshots`. No PR when no image changed.

Review the PRs: the images show what the dev fixtures render, a visual regression would appear in the diff.

### Unchanged images

Images contain dates, clocks and other values that move at every run (presence times, sale dates, "last update"…): without a filter, 40% of the images
changed on a run done a few minutes after the previous one, and most of them when run another day, which makes the pull requests unreadable.

`filter-unchanged.ts` compares every generated image with the one already committed in the target repository (checked out by the workflow)
and removes the ones where **less than 2%** of the pixels differ (a channel moving by more than 16/255). It keeps images that are new, resized or really different.
The list of kept / dropped images (with their difference) is in the job summary.

- `threshold` input: percentage of different pixels under which an image is considered unchanged (default `2`)
- `force` input: skip the filter and update every image
- locally: `pnpm exec tsx tests/screenshots/filter-unchanged.ts --docs ../documentation --about ../narvik-about [--threshold 2]`

A tiny UI change (a label, an icon) stays under the threshold and is picked up the next time the page changes enough, or with `force`.

## What can't be generated

- Screenshots of external tools (iTAC, Cerbère, Eden, FFTir…) in `docs/frontend/docs/import/images/import-donnees/`
- Hand-drawn annotations (red arrows): the images are generated without them, the doc text explains what to look at
- `membres/images/creation.png` (member creation form)
- About images not in the manifest yet (the ones still directly in `public/pics/`, outside `generated/`)
